# Hallpass web UI

Operator console for Hallpass (docs/PLAN.md §14, requirements `HP-UI-*` in docs/GOAL.md §6).
React 19 + TypeScript (strict) + Vite, TanStack Router/Query/Store, Ant Design with Hallpass theme
tokens, Apache ECharts, xterm.js.

Status: **WP19 foundation**. The design system, API client, live-event manager, stores, login/setup
flows and app shell exist. Operational pages (WP20) and session replay (WP21) are placeholders that
render an explicit "not implemented yet" state. They never show mock data.

## Commands

Requires Node 24 and pnpm 10 (`packageManager` is pinned in `package.json`).

| Command          | What it does                                                                                                                    |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `pnpm install`   | Install the exact pinned dependencies (`save-exact`, strict peer deps).                                                         |
| `pnpm dev`       | Vite dev server on :5173. Proxies `/api` and `/auth/oidc/callback` to `HALLPASS_DEV_API_URL` (default `http://127.0.0.1:8080`). |
| `pnpm lint`      | ESLint (typescript-eslint strict type-checked, jsx-a11y strict, react-hooks) and Prettier check.                                |
| `pnpm format`    | Prettier write.                                                                                                                 |
| `pnpm typecheck` | `tsc --noEmit`.                                                                                                                 |
| `pnpm test`      | Vitest (jsdom) unit and component tests.                                                                                        |
| `pnpm build`     | Typecheck, production build to `dist/` (gitignored), then `scripts/check-dist.mjs`.                                             |
| `pnpm preview`   | Serve `dist/` with the production CSP header from PLAN §12.3.                                                                   |
| `pnpm e2e`       | Playwright (Chromium, Firefox) with axe. Every spec is skipped unless `HALLPASS_E2E_URL` is set.                                |

E2E against a running backend:

```sh
pnpm exec playwright install chromium firefox   # once
HALLPASS_E2E_URL=http://127.0.0.1:8080 pnpm e2e
```

## Layout

```
src/
  api/          fetch client (CSRF, problem+json → ApiError, reauth retry, 401 → /login),
                hand-written types (to be replaced by openapi-typescript output), query keys/options
  sse/          EventSource manager for /api/v1/events and the resource → query-key invalidation map
  stores/       TanStack Store: theme, density, SSE status, server clock offset
  ds/           design system: theme tokens, components, the dev-only /__ds gallery
  features/     page implementations (auth, dashboard, me, placeholders)
  layout/       app shell, navigation, theme toggle
  routes/       TanStack Router file routes (routeTree.gen.ts is generated by the Vite plugin; commit it)
  devtools/     TanStack devtools, loaded only through an import.meta.env.DEV dynamic import
e2e/            Playwright specs
scripts/        build checks
```

## Conventions

### Security

- **No HTML from data.** `dangerouslySetInnerHTML`, `innerHTML`/`outerHTML` assignment,
  `insertAdjacentHTML`, `createContextualFragment`, `DOMParser.parseFromString` and `document.write` are
  lint errors. Agent- or destination-provided strings go through `ds/UntrustedText`, which renders text
  nodes, labels the text as untrusted, and shows bidi/zero-width/control characters as visible
  `<U+XXXX>` markers.
- **CSP.** Production uses `script-src 'self'`. `index.html` has no inline script, and
  `scripts/check-dist.mjs` fails the build if one appears. Ant Design's CSS-in-JS still needs
  `style-src 'unsafe-inline'` (PLAN §12.3, review item R-11).
- **No optimistic success.** Security mutations are never assumed to succeed. Use `ds/ConfirmAction`,
  which keeps its dialog open with a pending state until the server answers and calls `onSuccess` only
  after a 2xx response. Query mutations have `retry: false`.
- **CSRF.** Mutations send `X-CSRF-Token` taken from `GET /me` (`csrf_token`). After a reauth the
  session rotates, so the client refetches `/me` before it retries.
- **Reauth.** A `reauth_required` problem opens `ds/ReauthGate`. The original request is retried once
  after the operator reauthenticates, and is rejected if the operator cancels.
- **Redirects.** `?next=` is validated by `features/auth/redirect.ts`, which accepts same-origin paths only.
- **Replay.** `ds/terminal.ts` holds the hardened xterm options: read-only, an inert link handler,
  OSC 0/1/2/8/52 swallowed, no title/bell subscriptions.
- **Client permission checks are cosmetic.** `PermissionGate` hides UI. The server authorizes every request.
- **Dev-only code.** Devtools and the `/__ds` gallery sit behind `import.meta.env.DEV` and are absent
  from production bundles. `check-dist.mjs` verifies this.

### Data and state

- Server state lives in TanStack Query. Keys mirror resources (`api/queryKeys.ts`): list `[root, filters]`,
  detail `[singular, id]`.
- Live events invalidate queries through `sse/invalidation.ts`. The following invalidate everything:
  unknown resources, `reset`, a malformed frame, and the first open of every new EventSource (a new
  object cannot send `Last-Event-ID`).
- Client-only state lives in TanStack Store (`stores/`). Only UI preferences (theme, density) are
  persisted, through `try/catch`-guarded localStorage.
- Countdowns use server time: `Date.now() + offset`. The offset comes from API `Date` headers
  (`stores/clock.ts`).
- Every data view renders a real state from `ds/states.tsx` (loading, empty, error, permission denied,
  not implemented) and never placeholder data. Charts take their data only from real `/stats/*` endpoints.

### Design system

- Tokens live in `ds/theme/tokens.ts`: radius 4 (cards/overlays 6, small 2), controlHeight 32, compact
  28 px table rows, a shadow on overlays only, no pills or gradients. Light and dark themes use
  `theme.darkAlgorithm` plus explicit overrides.
- Text colors are explicit. `ds/theme/contrast.test.ts` asserts WCAG AA (4.5:1) for every text token
  on every surface in both themes. Run it after any palette change.
- Static styles live in `ds/ds.css` and use the `--hp-*` variables that `ThemeProvider` derives from
  the resolved tokens.
- `pnpm dev` and then `/__ds` shows every component in both themes. Playwright visual snapshots will
  target this page.

### Code

- Strict TypeScript (`noUncheckedIndexedAccess`, `verbatimModuleSyntax`). Use exact dependency versions only.
- Test files sit next to their code (`*.test.ts(x)`). Tests generate their own fixtures and contain no secrets.
- Avoid file names that differ only by case (macOS file systems are case-insensitive). Example:
  `countdownMath.ts` sits beside `Countdown.tsx`.

## Known gaps (tracked in WP19 / later packages)

- API types are hand-written and partly **provisional**: the bodies for login, MFA, reauth and bootstrap,
  the `return_to` parameter for OIDC start, the problem `errors[]` field naming, the login-CSRF cookie
  name, and the SSE `resource` names. Reconcile them with `api/openapi.yaml` once it exists, then switch
  to `openapi-typescript`.
- No Go embedding of `dist/` yet (HP-UI-016).
- The setup page does not enroll TOTP yet, and ReauthGate has no OIDC step-up.
- The Playwright suite has one smoke/axe spec. It does not yet cover login flows in all three modes, axe on
  every route, or visual snapshots of `/__ds`. Those need a running backend.
- `/system/time` clock sampling, the DataTable column chooser and saved filters, and the `Timeline`
  component are not implemented.
