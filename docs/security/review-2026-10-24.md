The core authorization paths hold up:

- agent identity from the verified key;
- default-deny policy with identical hidden and unknown responses;
- one transactional decision service for web, Slack and Telegram;
- CAS state transitions;
- strict destination host verification and the egress guard;
- HPREC1 frame cryptography;
- verify-before-parse webhooks;
- CSRF, Origin and CSP.

The serious problems are in two areas:

1. **Second-factor lifecycle (SR-01, SR-03..SR-05).** A stolen password is enough to become a full administrator (SR-01).
2. **Integrity verification and recording metadata (SR-02, SR-16, SR-17).** A party without keys can hide recordings and `hallpass verify` still passes. This contradicts G-9.

Several items are marked "tested" or "done" in PLAN.md but are not reachable in production:

- the self-approval prohibition (SR-14);
- the break-glass recovery login (SR-07);
- recording-key rewrap and startup slot repair (SR-39).

Under AGENTS.md, those status entries must be corrected.

## 1. HIGH findings

### SR-01: MFA bypass through `POST /api/v1/me/mfa/totp/confirm` on an already-enrolled factor

- **Severity: HIGH.** A stolen password alone yields a full, recently-authenticated administrator session that passes MFA gates. The attacker also gets fresh recovery codes (persistence) and the victim's sessions are revoked.
- **Where:**
  - `internal/opauth/mfa.go:74`: `VerifyTOTP(secret, code, now, 0)` ignores `t.LastStep`.
  - `mfa.go:83`: the `:execrows` result of `ConfirmTOTP` is discarded. The SQL at `internal/store/queries/operators.sql:66` (`... AND confirmed_at IS NULL`) matches 0 rows for a confirmed factor, and the code carries on anyway.
  - `mfa.go:85-96`: it then stores new recovery codes, revokes all other sessions and sets `auth_at = mfa_at = now` on the same token.
  - The route is `x-permission: session.limited` (`api/openapi.yaml:220-222`, `internal/httpapi/gen/operations.gen.go:63`), so an MFA-pending session may call it.
  - Its path is under `/api/v1/me/`, so the strict `auth:` per-IP limit (`internal/httpapi/server.go:255-259`) does not apply. There is no `recordFailure` call and no failure audit.
- **Exploit:**
  1. Log in with the victim's password. The result is a `mfa_pending` (Limited) session.
  2. Either replay a code the victim just used, which `/auth/mfa` correctly rejects but this endpoint accepts within the ±1 step window, or brute-force 6-digit codes at the per-session API rate. About 3 of 10^6 codes are valid per guess, and sessions can be multiplied.
  3. The response is 200 with 10 new recovery codes.
- **Reproduction:** two reviewers confirmed this independently with probes.
  - The API probe showed `/auth/mfa` returning 401 for the replayed code while `/me/mfa/totp/confirm` returned 200 with codes. After that, `GET /agents` returned 200 and `POST /invitations` (reauth+MFA gated) returned 200. 50 wrong codes were all answered 422, never throttled.
  - The opauth probe showed `limited=false mfaAt=true sameToken=true` and the attacker session passing `RequireRecentAuth(MFA)`.
- **Violates:** HP-AUTH-006 (no step reuse), HP-AUTH-004 (throttling), HP-AUTH-008 (mandatory MFA), HP-AUTH-012 (rotation). Threats T-07 and T-11.
- **Fix:**
  - Refuse up front when `t.ConfirmedAt.Valid`, or require `rows == 1` before any side effect.
  - Pass `t.LastStep`.
  - Apply the `mfa:`+operator throttle and audit failures.
  - Allow the route for Limited sessions only when `NeedsEnroll`.
  - Rotate the session instead of `UpdateWebSessionAuth`. Add a regression test that replays a consumed code on confirm.

### SR-02: Integrity verification does not bind the chain to segment metadata; keyless hiding and truncation goes undetected

- **Severity: HIGH.** This defeats G-9, "truncation and tampering by a party without the keys are detected", in the primary verification command, which still exits 0. The attacker needs write access to the SQLite file and the segment files but no keys.
- **Where:**
  - `internal/recording/reconcile.go:282-314` (`verifyChain`) checks the links, hashes and MACs over the stored `manifest_sha256` only. It never recomputes a manifest from the current `recording_segments` row.
  - `reconcile.go:219-221` (`allSegments`) omits `deleted` rows.
  - `reconcile.go:234-236` reports `failed` and `deleted` segments as "skipped".
- **Exploit (probe, 3 finalized segments):**
  - (a) Truncate segment 0 after its key slots and set its row to `interrupted`, `ciphertext_sha256 = sha256("")`, `frames = 0`.
  - (b) Delete segment 1 and set its row to `failed`.
  - (c) Delete segment 2 and set its row to `deleted`.
  - Output: `OK=true chainOK=true len=3`. Segment 0 is reported `interrupted`, segment 1 `skipped`, and segment 2 is not listed.
  - `anchors verify` (`internal/backup/anchors.go:249`, `checkEntryManifest`) caught (a) and (b), but only up to the last exported anchor. It missed (c) (see SR-17).
- **Violates:** HP-CRY-005, G-9, T-15. PLAN §21 marks HP-CRY-005 "tested", which overstates the coverage.
- **Fix:**
  - In `verifyChain`, recompute each entry's manifest from the current row, as `backup.checkEntryManifest` already does.
  - Treat a missing row or mismatched metadata as corrupt.
  - Verify `failed` and `deleted` rows that have a chain entry, and include `deleted` in `allSegments`.

## 2. MEDIUM findings

### SR-03: Recent-auth and IdP step-up bypass through TOTP-only paths

- **Severity: MEDIUM.** It needs a stolen full session, but it defeats HP-AUTH-014 and a provider's `stepup_fallback: none`.
- **Where:** three paths.
  - **(a) Enrollment.** `internal/opauth/mfa.go:34-39` (`BeginTOTP`) needs no recent auth when no factor is confirmed. `mfa.go:94` then sets `auth_at = now`. On an SSO session, or a local session where MFA is not required, an attacker enrolls their own TOTP and passes every reauth+MFA gate.
  - **(b) `ReauthTOTP`.** `internal/opauth/external.go:60-83` never checks that the session is OIDC or that the provider's `StepUpFallback == local_totp`. It therefore works on password sessions without the password.
  - **(c) `VerifyMFA`.** `internal/opauth/login.go:203-245` runs on non-Limited sessions. It re-creates the session as `MethodPassword` (`:237`) and drops `Provider`.
- **Reproduction (probe):** an SSO session 10 minutes old fails `RequireRecentAuth(MFA)`. It passes after `BeginTOTP` + `ConfirmTOTP` on the same unrotated token, and also passes after `ReauthTOTP` with `stepup_fallback=none`. `VerifyMFA` on a full SSO session gives `method=password provider=""`.
- **Violates:** HP-AUTH-014, HP-OIDC-013, ADR-0030.
- **Fix:**
  - Enrollment sets `mfa_at` only, and only on Limited or `NeedsEnroll` sessions.
  - First enrollment on a full session requires recent auth.
  - `ReauthTOTP` is restricted to OIDC sessions whose provider has `local_totp` fallback.
  - `VerifyMFA` is restricted to Limited password sessions and keeps method and provider.

### SR-04: Abandoned TOTP re-enrollment silently removes the confirmed factor

- **Severity: MEDIUM.** It disables MFA with no audit event and without `DisableTOTP`'s gates. For an MFA-required role, a password-only attacker can then enroll their own factor.
- **Where:** `internal/opauth/mfa.go:49` calls `UpsertTOTP`. The SQL at `internal/store/queries/operators.sql:61-63` overwrites `secret_enc` and sets `confirmed_at = NULL, last_step = 0`. `MFAEnrolled` is derived from `confirmed_at`.
- **Reproduction (probe):**
  1. An admin calls `POST /me/mfa/totp` and never confirms. `/me` now shows `mfa_enrolled:false`.
  2. An attacker logs in with the password and gets `must_enroll=true`.
  3. The attacker's `beginTOTP` and `confirmTOTP` both return 200, and `GET /operators` returns 200.
- **Violates:** HP-AUTH-014 (MFA disablement needs recent auth + MFA), HP-AUTH-010.
- **Fix:** store the pending secret separately and replace the confirmed one only on a successful confirm.

### SR-05: No failure throttling on reauthentication and password change

- **Severity: MEDIUM.** A stolen full session can guess the TOTP code to pass reauth+MFA gates. That is about 73% success within the 12 h absolute lifetime at the 600/min per-session cap spread over IPs (analytic estimate, not run).
- **Where:** `internal/opauth/login.go:284-330` (`Reauth`), `internal/opauth/external.go:60-70` (`ReauthTOTP`) and `login.go:333-349` (`ChangePassword`). `checkSecondFactor` (`login.go:248`) records nothing on failure; only `VerifyMFA` (`login.go:206-224`) throttles.
- **Violates:** HP-AUTH-004.
- **Fix:**
  - Share the `mfa:`+operator throttle key across `VerifyMFA`, `Reauth`, `ReauthTOTP` and `ConfirmTOTP`.
  - Throttle password failures in `Reauth` and `ChangePassword` with the account key.
  - Audit failures.
- **Status:** confirmed by code reading.

### SR-06: SSO-only administrator lockout

- **Severity: MEDIUM.** It leads to total admin lockout, and per SR-07 break-glass cannot recover from it.
- **Where:**
  - `internal/oidc/flow.go:604-619`: the `syncTx` guard counts all enabled admins, including local admins who cannot log in under SSO-only.
  - `internal/opauth/service.go:282-389`: `SetRoles` and `SetEnabled` use only `ensureAdminRemains`.
  - `checkSSOOnlyStillSafe` is called only from `internal/oidc/provider.go:521,546` and `internal/oidc/admin.go:123`.
- **Reproduction (probe):**
  - With SSO-only on, the IdP removes the admin group from the only SSO admin. Result: `CountSSOAdmins=0 localLoginDisabled=true`, and local admin login reports "password login is disabled".
  - `SetEnabled(onlySSOAdmin, false)` also succeeds.
- **Violates:** HP-AUTH-015.
- **Fix:**
  - When `local_login_disabled`, call `checkSSOOnlyStillSafe` in `SetRoles`, `SetEnabled` and `UnlinkIdentity`.
  - Have `syncTx` count SSO-capable admins (`CountSSOAdmins`).

### SR-07: Break-glass recovery login is unreachable

- **Severity: MEDIUM.** The documented last-resort recovery path does not work, and its status is overclaimed.
- **Where:**
  - `opauth.RecoveryLogin` (`internal/opauth/login.go:370`) has no caller outside tests.
  - There is no operation in `api/openapi.yaml` or `gen/operations.gen.go`, and no `recover` route in `web/src/routes`.
  - `cmd/hallpass/admin_cmd.go:21,99-105` prints a `/recover` URL and token that nothing accepts.
  - `--new-admin` creates an admin whose random password is never shown.
  - `docs/PLAN.md` §21 marks HP-AUTH-016 tested.
- **Violates:** HP-AUTH-016, T-20, and the AGENTS.md rule against redefining unfinished work as done.
- **Fix:**
  - Add a public, Origin-checked, auth-rate-limited `POST /api/v1/auth/recover` that calls `RecoveryLogin` and sets the cookie, and add a `/recover` page.
  - Downgrade the PLAN status until then.
- **Status:** confirmed by route and caller search.

### SR-08: Address disclosure through audit event details

- **Severity: MEDIUM.** This breaks the address-confidentiality guarantee for the default Auditor role, which holds `audit.read` but not `inventory.address.read` (`internal/rbac/rbac.go:75`).
- **Where:** `internal/httpapi/dto.go:343-351` (`auditEvent`) returns `details` verbatim, via `internal/httpapi/h_access.go:503-530`. The address-bearing details come from:
  - `internal/inventory/inventory.go:246` (`server.created`: address and port);
  - `inventory.go:331-333` (`server.updated`: address and `previous_address`);
  - `internal/inventory/hostid.go:352` (host-CA principals);
  - `internal/credentials/credentials.go:273-291` (raw `probeErr.Error()`, e.g. `dial tcp 10.0.0.5:22: ...`);
  - `internal/sshproxy/proxy.go:610` (`err.Error()` in `host_key_mismatch`).
- **Reproduction (probe, OIDC Auditor):**
  - `"action":"server.created",...,"details":{"address":"10.1.2.3",...,"port":2202}`
  - `"action":"credential.probed",...,"error":"dial tcp 10.255.254.253:2203: i/o timeout"`
  - The same caller's `GET /servers/{id}` is correctly redacted.
- **Violates:** HP-RBAC-002, HP-SRV-010.
- **Fix:**
  - Move address, port, principals and raw dial errors into `audit.Event.Sensitive` (sealed, `internal/audit/audit.go:72`), or redact them per caller in `auditEvent`.
  - Classify probe and host-key errors with the address-free `failureDetail`.

### SR-09: SSE defeats the idle session timeout

- **Severity: MEDIUM.** Any open UI tab keeps the session valid until the 12 h absolute limit, with no user activity.
- **Where:** `internal/httpapi/sse.go:258-262` re-validates with `Auth.Authenticate` every 30 s. `internal/opauth/sessions.go:137-141` updates `last_seen_at` on every `Authenticate` call made more than one minute after the last.
- **Reproduction (probe, fake clock):** 60 minutes after login with no requests, the control session returns 401 and the session holding an SSE stream returns 200.
- **Violates:** HP-AUTH-012 (idle expiry), T-11.
- **Fix:** use a non-touching validation for the SSE re-check, and close the stream once idle expiry has passed.

### SR-10: Account linking without recent auth; chat links outlive revocation

- **Severity: MEDIUM.** A stolen session becomes persistent chat approval power that survives the standard incident response (revoke sessions, reset the password).
- **Where:**
  - `api/openapi.yaml:1368-1372` and `internal/httpapi/gen/operations.gen.go:65`: `createProviderLinkCode` is `session` with no reauth or MFA. The admin `linkOperatorProvider` requires both (`:93`).
  - `internal/oidc/flow.go:141`: the self-link `purpose=link` requires only `MFASatisfied()`.
  - Nothing outside `internal/notify/sink.go:367` deletes `provider_links`. Not `RevokeAllSessions`, password reset or `DisableTOTP`.
  - The chat MFA gate (`internal/notify/sink.go:101-108`) checks only that the operator has a factor enrolled or a linked SSO identity.
- **Reproduction (probes):**
  - With the clock advanced 10 minutes, `POST /invitations` returns 401 `reauth_required`, but `POST /me/provider-link-codes` returns 200 with a code.
  - In the notify probe: link, then `RevokeAllSessions`, then a chat approve gives `state=approved`.
- **Violates:** HP-AUTH-014 ("account linking"), the intent of HP-NTF-011, R-10 / ADR-0035, T-11.
- **Fix:**
  - Add `x-reauth: true` and `x-mfa: true` to `createProviderLinkCode`, and call `RequireRecentAuth` for `PurposeLink`.
  - Delete or suspend provider links on revoke-all, password reset and MFA reset.
  - Notify the operator when a new link is created.

### SR-11: Plaintext invitation tokens persisted in the idempotency table

- **Severity: MEDIUM.** One-time tokens are otherwise MAC-only specifically so that AD-8 (DB or backup read without the KEK) cannot use them. Here an unused administrator invitation can be redeemed from a DB copy or backup taken within 24 h.
- **Where:** `internal/httpapi/support.go:131-141` stores the full response body. `createInvitation` honours `Idempotency-Key` (`internal/httpapi/h_auth.go:426`), and its response contains `token`.
- **Reproduction (probe):** after `POST /invitations` with `Idempotency-Key`, the `api_idempotency` row contained the token in plaintext. `one_time_tokens` held only the MAC.
- **Violates:** HP-AUTH-018, AS-7, T-08.
- **Fix:** do not cache secret-bearing responses. Store only a hash and status and return 409 on replay, or seal the cached body.

### SR-12: Membership and inventory changes do not trigger policy reconciliation

- **Severity: MEDIUM.** HP-POL-008 needs effect within the 5 s bound. Existing channels survive up to 60 s after access is withdrawn. New channels are blocked at once.
- **Where:**
  - `internal/agents/service.go:206,299,347`, `internal/inventory/inventory.go:242,327,361` and `internal/inventory/roles.go:188,242,275` bump `policy_version` but publish only `agent.changed` or `inventory.changed`, which have no subscriber.
  - Only `internal/policy/service.go:36-45` publishes `policy.changed`.
  - `internal/access/reconcile.go:80-107` reconciles on `policy.changed` or a 1-minute ticker.
- **Reproduction (probe):** an agent was removed from its only allowing group. After 3 s: `grant state=active policy.changed events=0`. A manual `ReconcilePolicy` then gave `revoked=1`. The same delay applies to lowering a role's `max_duration` and to group or label edits.
- **Violates:** HP-POL-008, HP-GRT-008.
- **Fix:** publish `TopicPolicyChanged` from every transaction that bumps the version. Centralise bump plus publish in one helper.

### SR-13: The enforcer's DB safety net stalls on 1000 or more rows with the same timestamp

- **Severity: MEDIUM.** Once it stalls, lost grant events are never reconciled until restart, so revoked grants keep running until expiry.
- **Where:** `internal/store/queries/access.sql:96` (`WHERE updated_at > ? ORDER BY updated_at LIMIT 1000`) and `internal/access/enforcer.go:241-260` (the cursor is the max `updated_at` returned).
- **Why it stalls:** mass revocations stamp every row with one `tx.NowMicros()`. These include lockdown, server or role disable, and `ReconcilePolicy`. They also publish more than 1000 events into the enforcer's 1024-slot queue (`enforcer.go:286`), so those events can be dropped, which is exactly the case the safety net exists for.
- **Reproduction (probe):** 1000 revoked grants inserted in one transaction, then a live grant revoked with its event lost. Output: `channel still live=true` on all 5 passes across 50 s of fake time.
- **Violates:** HP-GRT-008, G-4.
- **Fix:** page with a compound `(updated_at, id)` cursor and loop until a short page comes back. Keep the overlap re-read separate.

### SR-14: The self-approval prohibition is unreachable in production

- **Severity: MEDIUM.** A default-on security control is a no-op, and PLAN marks it tested.
- **Where:** `policy.Service.SetAgentOwners` (`internal/policy/service.go:276`) and `SetProhibitSelfApproval` (`:307`) have no non-test callers. Nothing in the API, UI or CLI sets them, `agents.Create` records no owner, and nothing else inserts into `agent_owners`. The owner check in `CanApprove` (`internal/policy/snapshot.go:436`) therefore never matches.
- **Violates:** HP-POL-012, HP-RBAC-003, AGENTS.md (status overclaim).
- **Fix:** expose admin-only, audited owner management, or record the creator as owner. Downgrade the status until then.
- **Status:** confirmed by grep across Go, OpenAPI and web.

### SR-15: A connection authenticated with a revoked key keeps control-plane access

- **Severity: MEDIUM.** The holder of a compromised key that has been revoked keeps an open connection. Through it they can enumerate visible targets and file requests. With an auto-approve rule, they obtain agent-wide grants that the agent's other keys can use.
- **Where:**
  - `internal/access/requests.go:47-160` (`CreateRequest`) never checks the key's state.
  - The enforcer kills only destination channels.
  - `internal/sshfront/server.go` (`serveConn`) does not close connections on `agent.key.revoked`.
  - `internal/access/channels.go:141` correctly blocks new destination channels.
- **Reproduction (probe):** first key revoked, auto-approve rule in place. Output: `revoked key ...: request ... state=approved autoApproved=true grant=true`.
- **Violates:** HP-AGT-005 (connections using a revoked key are terminated), T-02.
- **Fix:**
  - Check that the key is active and belongs to the agent inside `CreateRequest`'s transaction.
  - Close SSH connections by key ID on key revocation, and by agent on disable, within the bound.

### SR-16: Segment paths are not confined to `recordings/`

- **Severity: MEDIUM.** It needs write access to backup storage plus an operator restore. The result is deletion of any file the gateway user can remove, and export of any file it can read, which could include the KEK file, to a holder of `recording.export`.
- **Where:**
  - `internal/backup/restore.go:184-187`: `rewritePaths` silently keeps paths that do not match the old prefix.
  - `internal/backup/verify.go:285` matches rows by segment ID, not by path. The manifest is protected only by an unkeyed SHA-256.
  - The path is used as-is by `internal/recording/reconcile.go:364-365` (`os.Remove`), `internal/httpapi/h_export.go:75-76` and `reconcile.go:386-397` (`ReadPage`).
- **Reproduction (probe):**
  1. In a backup's DB copy, point `recording_segments.path` at a file outside the data dir, set the session `delete_after=1`, and recompute `manifest.json` and `manifest.sha256`.
  2. `backup verify` reports `ok=true` and restore succeeds.
  3. Retention runs with `deleted=1`, and the victim file is gone.
- **Violates:** HP-OPS-004 (safe restore), HP-REC-013. The checklist's restore path-traversal item fails for paths held in the DB.
- **Fix:**
  - At restore verify, reject any row whose path is not `<data>/recordings/<shard>/<session>/<id>.hprec`, and require it to match the manifest entry.
  - At runtime, check `filepath.IsLocal` against the recordings dir before every use, or derive paths from IDs.

### SR-17: Retention deletion is unaudited, and `deleted` passes verification

- **Severity: MEDIUM.** Recording evidence can be erased with no trace, and the erasure looks the same as legitimate retention.
- **Where:** `internal/recording/reconcile.go:327-385` (`ApplyRetention`) writes no audit event and does not tie `deleted` to `delete_after`. `internal/backup/anchors.go:269-271` accepts `deleted` whenever the manifest recomputes.
- **Reproduction:** attack (c) in SR-02 passes both `verify` and `anchors verify`.
- **Violates:** HP-REC-013 ("audited tombstone"), PLAN §13.9, T-15.
- **Fix:**
  - Write a hash-chained audit event for each deletion, in the same transaction as `MarkSegmentDeleted`.
  - Accept `deleted` in verification only when the session is past `delete_after` and a matching tombstone exists.

### SR-18: Backups break permanently after KEK rotation when retired keys exist

- **Severity: MEDIUM.** Backups are lost as an operational control, and the error message points the operator at the wrong fix.
- **Where:** `internal/keyring/keyring.go:516-518` (`RotateKEK`) skips retired rows, which keep the old `wrap_kek_id`. `internal/backup/backup.go:276-277` (`SELECT DISTINCT wrap_kek_id FROM keyring_keys`) counts them, and backup creation refuses with "several KEKs". Re-running `rotate-kek` cannot fix it.
- **Reproduction (probe):** rotate the token key, retire v1, then run `RotateKEK`. Backup then fails with `keyring keys are wrapped under several KEKs (...); finish hallpass keys rotate-kek first`.
- **Violates:** HP-OPS-003, HP-CRY-002.
- **Fix:** ignore retired rows in `kekIDs` (and in verify), or have `RotateKEK` rewrap or purge retired rows as PLAN §13.1 describes.

### SR-19: A key flood starves the webhook and collector rate limiters

- **Severity: MEDIUM.** It is unauthenticated and cheap. It drops Slack clicks and can drop destination-audit records.
- **Where:**
  - `internal/ratelimit/window.go:39-46`: once `MaxKeys` (4096) is reached, an unseen key shares one overflow window.
  - The limiters (`internal/notify/webhooks.go:15,28`, 20/s per integration ID; `internal/app/serve.go:194-196`, 10/s per collector ID) run before any authentication. A real integration or collector idle for more than 1 s is pruned and lands in the saturated overflow.
  - The collector retries 3 times (`internal/destaudit/collector/ship.go:176,207`), then `cmd/hallpass-collector/main.go:182-183` drops the batch.
- **Reproduction (probe, verbatim copy of the limiter):** with 4136 bogus IDs per second, the real integration got `allowed=0 denied=5`. Separately, anyone who knows an ID can block it at about 21 requests/s.
- **Violates:** HP-NTF-012, HP-REC-012 (completeness). HP-NTF-010 still holds: nothing is approved because of this.
- **Fix:**
  - Rate-limit per source IP first.
  - Don't count unknown IDs against the shared table (check against a cached ID set).
  - Reserve slots for known IDs.
  - Have the collector spool to disk and retry instead of dropping.

### SR-20: Unthrottled denial audits from authenticated agents

- **Severity: MEDIUM.** One compromised agent (AD-1) can push unbounded writer transactions and audit rows. The likely end state is the disk reserve tripping, which refuses all new channels, plus writer contention and real events buried in noise.
- **Where:** `internal/sshfront/server.go:421-426` (refused channel types), `:439-451` (refused global requests) and `internal/sshfront/session.go:118-123` (refused session requests). Each goes through `AuditDenied` (`server.go:454-462`), which is one `TxNamed` per event with no limiter.
- **Reproduction (probe in the fault harness):** 3000 `tcpip-forward` requests on one connection gave `2999 denied rows` in 7.4 s. The agent limits allow 32 connections.
- **Violates:** T-01, T-22, HP-SSH-007 (audit design).
- **Fix:** rate-limit denial audits per connection and per agent, with aggregated "suppressed=N" events. Close the connection after M refusals.

### SR-21: The global sequencer mutex is held across a writer transaction (P-2 only partly fixed)

- **Severity: MEDIUM.** Under a storage stall, every channel's recorder blocks on one mutex, well beyond `recording.block_timeout`. This breaks the HP-REC-011 termination bound. G-8 still holds: the pumps are blocked, so nothing unrecorded is forwarded.
- **Where:** `internal/access/service.go:262-286`: `q.mu.Lock()` is taken on every call, including when a cached block suffices, and is held through `TxNamed`. Callers without a deadline, such as `CloseConnection` and `CloseChannel` (`context.WithoutCancel`) and the `recFail` path, keep it held for up to 5 × 5 s `busy_timeout` or indefinitely. Fix fee9b40 only bounded the recorder's own context (`internal/recording/recorder.go:290-292`).
- **Reproduction (probe):** the DB write lock was held, and another session's `Next(context.Background())` was started. A `Next` for a session with a cached block and a 1 s deadline then `took 25.446s`. `TestFI08StalledStorage` passes only because it has a single channel.
- **Violates:** HP-REC-011. P-2's status ("fixed") is wrong.
- **Fix:** serve cached blocks without the global lock, use per-session reservation (singleflight), and give every caller a bounded context.

### SR-22: The pre-auth per-source limit is keyed by exact address

- **Severity: MEDIUM.** It allows an unauthenticated denial of service of every agent. The attacker holds 256 idle connections from one IPv6 /64, refreshes them every 10 s, and is never banned, because handshake timeouts do not count toward bans (HP-SSH-026).
- **Where:** `internal/sshfront/server.go:207-231` (`perIP map[netip.Addr]int`, keyed by the full address). `sshban` already keys IPv6 by /64.
- **Violates:** the intent of HP-SSH-013, and T-22.
- **Fix:**
  - Key by `sshban.Source(ip)`, with an optional /48 or /56 tier.
  - Use random early drop near the global cap.
  - Consider counting repeated pre-auth timeouts as penalties. That needs an ADR, since HP-SSH-026 excludes plain connects.
- **Status:** confirmed by code. It was not exercised end to end because loopback has no spare IPv6 range.

## 6. Checklist coverage

"Verified" means the reviewer read the code path and found it correct. It does not mean an external party verified it.

### 1.1 Agent SSH authentication

- **Identity from the verified key only: verified.** `internal/sshfront/server.go:248-256,335-340`. x/crypto v0.58 caches a single key, so Permissions belong to the verified key (the CVE-2024-45337 class does not apply). There is no password, keyboard-interactive or none auth.
- **Algorithms on the agent leg: verified.** `internal/sshalg/sshalg.go:36-43` excludes `ssh-rsa`. `internal/agents/keys.go:78-116` requires RSA ≥ 3072 and rejects certificates and sk-* keys. KEX, cipher and MAC lists apply on both legs. The destination-leg host-key and CA floor is **finding SR-45**.
- **Uniform rejection: verified.** `internal/agents/service.go:592-635`, including address unmapping for source CIDRs.
- **Revocation and disable block new auth and channels: verified.** Live control-plane connections are **finding SR-15**.
- **Pre-auth limits, handshake timeout and per-agent limits: verified** at `server.go:297,311,393-402,428-435`. The per-source keying is **finding SR-22**.

### 1.2 Operator authentication

- **Argon2id, `dummyHash` and enumeration: verified.** m=64 MiB, t=3, p=2 (`internal/opauth/password.go:37-39`). Unknown, disabled and SSO-only accounts do the same work (`login.go:132-170`).
- **NFKC normalization: verified.** 1024-byte reject, no truncation (`password.go:45-59`). PHC bounds are checked (`:75-96`).
- **TOTP on the login path: verified.** ±1 step, `hmac.Equal`, atomic `AdvanceTOTPStep` (`totp.go:48-62`, `login.go:262`). The secret is sealed with an operator AAD. The enrollment path has **findings SR-01, SR-03 and SR-04**.
- **Sessions: verified.** 256-bit token, SHA-256 at rest, idle and absolute checks, roles re-read on every request (`sessions.go:57-143`). The CSRF token is an HMAC compared in constant time (`sessions.go:145-154`). Rotation is **finding SR-27**; idle bypass through SSE is **finding SR-09**.
- **One-time tokens: verified.** MAC-only storage, atomic single use and expiry in SQL (`tokens.go:32,47-74`). A reset revokes sessions (`tokens.go:263-272`). There is a plaintext copy in the idempotency table (**finding SR-11**). Break-glass is unreachable (**finding SR-07**).
- **Throttling and lockout: verified for login.** Exponential backoff, 15 min cap, no permanent lockout, IPv6 keyed by /64 (`login.go:30-80`). Reauth throttling is **finding SR-05**; the SSO-only admin lockout is **finding SR-06**.

### 1.3 OIDC

- **ID token checks: verified.** Only RS256, ES256 and EdDSA. Exact `iss`, `aud`, and `azp`. `exp`, `iat` and `nbf` with 60 s skew. Nonce hashed and compared (`internal/oidc/flow.go:359-407`). RSA ≥ 2048, EC P-256, symmetric keys refused, JWKS refetch rate-limited (`remote.go:35-37,196,231-280`).
- **State, PKCE and nonce: verified.** Server-side, single use (`DELETE ... RETURNING`), 10 min TTL, browser binding cookie compared in constant time, PKCE verifier sealed (`flow.go:153-181,250-268`).
- **Redirect safety: finding SR-24.**
- **Linking and provisioning: verified.** `iss`+`sub` identity, no email merge, JIT conflicts refused, group allowlist (`flow.go:426-561`). Role persistence is **finding SR-26**, the last-admin guard **finding SR-06**, and self-link reauth **finding SR-10**.
- **Provider egress: verified.** TLS always verified, no proxy, no redirects, private ranges refused at dial time, same-site endpoints (`remote.go:57-167`, `provider.go:287-299`).

### 2. Grammar and exec forwarding

- **No shell; byte-exact remote command: verified.** UTF-8, C0 and size checks over the whole input; the remote command is the raw suffix, recorded and executed identically (`internal/sshfront/grammar/tokenize.go:56-69,131-142`, `internal/sshproxy/proxy.go:341-347`).

Connect failures are generic (`session.go:619-629`). No timing measurement was taken.

No `InsecureIgnoreHostKey` outside the analyzer's testdata.

The footer count and hash are checked. Segment, session and channel substitution is caught by the `Expect*` options. The metadata and chain layer has **findings SR-02, SR-17 and SR-38**; the rewrap path **finding SR-39**.
